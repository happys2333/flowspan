## Actual test-first observations

Seven incremental tracer/fault rows were observed RED before their respective
implementation changes, then GREEN. These are actual runtime failures, not
invented mutation results. Early interface accessibility scaffolding errors were
fixed before obtaining the runtime Start-failure RED.

| RED diagnostic case | GREEN change |
| --- | --- |
| `timespec_layout` | signed 64-bit fields; final checks size 16, offsets 0/8 and >32-bit seconds |
| `start_failure_releases_native_owners` | returned Start failure still joins Stop, destroys known loop and pairs deinit |
| `successful_roundtrip_observes_and_releases` | recursive lock/unlock, outside-thread and time facts, complete drain |
| `version_output_is_bounded_and_injection_safe` | bounded ASCII version vocabulary; no newline/key-value injection |
| `invalid_version_fails_before_loop_allocation` | reject bad version before allocation, pair completed init/deinit |
| `worker_timeout_retains_borrowed_owner` | bounded outer join; no Stop/Destroy/deinit while fake Start is borrowed |
| `default_zero_time_is_not_observable` | reject successful GetTime with default-zero out storage |

The remaining fault rows and maximum-output check were added against the already
implemented behavior; they are not claimed as additional observed RED cases.
The timeout fake uses a 10-ms outer join and a blocked Start boundary, verifies
no native-owner cleanup before release, then releases and joins the exact worker
and proves one completed cleanup. Its original timeout result stays immutable.
The production tool path uses a 15-second join, not the test's shorter budget.

The native time requirement is specifically an observable nonzero returned time
with valid fields. It does not make zero timespec universally invalid, does not
prove a monotonic clock, and does not prove native event/capture callbacks.
