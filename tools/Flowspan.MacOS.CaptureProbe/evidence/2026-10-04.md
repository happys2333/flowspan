## Observed results

Both default runs reported `mode=synthetic-only`, 1,000 copied native Block
callbacks, 1,000 synthetic native output/sample cycles, zero remaining Block
GCHandles, and zero retained synthetic samples. They explicitly reported
`preflight_called=false`, `AppKit_initialized=false`, and
`native_capture_executed=false`. No native-capture success is inferred from them.

The explicit native runs found capture preflight already Granted. They created
only their own 64×64 window, used current-process-only redacted shareable-content
enumeration, and matched PID plus exact windowNumber. Each consumed one Complete
frame with exact 4,096-byte interior marker hash `e92fac80964c0b25`; full-frame
hash was `9e913b9daaa62825`. Each observed one native callback. Both reported
successful Stop, output removal, queue drain, and zero late callbacks during
505 ms (Debug) / 501 ms (Release) post-drain observation. Frame copies were bounded
to 16,384 bytes; no pixel file was written. All native completion Block contexts
were drained at exit.

SDK declaration compilation to LLVM IR was actually repeated for arm64 and
x86_64 using the README commands, with exit 0. Both emitted the output method
encoding `v40@0:8@16^{opaqueCMSampleBuffer=}24q32`. This is only compile-time Intel
ABI evidence, not Intel execution evidence.

Independent read-only review of this exact source hash returned APPROVE with no
remaining P0/P1/P2 within the standalone-tool scope. That review did not execute
capture or establish native fault-injection results.

## Limits

This demonstrates feasibility on this matching local host only. It does not
certify a production adapter or complete a v1 acceptance gate. Non-Granted Skip,
permission revocation, native failure/timeout injection, a hung GCD barrier,
source disappearance, blocked downstream consumers, protected-window policy,
external emergency stop, physical two-device use, packaged TCC identity,
leak-detector runs, signing/notarization, Intel runtime, and arm64e remain
unverified. The tool's repaired exception/timeout paths were reviewed; do not
describe them as observed native fault-injection results. The ≥500 ms check
does not prove that callbacks can never arrive later.
