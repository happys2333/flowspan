## Actual TDD sequence and regressions

Each RED was actually run through Debug `dotnet run ... -- --wgc-self-test`,
then minimal implementation was added before the next behavior:

1. ContentSize 33x16 outside Surface 32x16: RED exit 1,
   `wgc_self_test=fail type=NotImplementedException`; GREEN exit 0, cases=1.
   The borrowed frame closes, no GPU-copy boundary is invoked, and no pixels
   are returned.
2. Stop while the native-copy boundary is blocked: RED exit 1,
   `wgc_self_test=fail type=InvalidOperationException`; GREEN exit 0, cases=2.
   The resumed copy is cleared, the frame closes, and no owned pixels escape.
3. Failed native Close: RED exit 1,
   `wgc_self_test=fail type=NotImplementedException`; GREEN exit 0, cases=3.
   Both original and QI outrefs remain quarantined; no Release is called.
4. Stop during native description: RED exit 1,
   `wgc_self_test=fail type=InvalidOperationException`; GREEN exit 0, cases=9.
   Copy is not entered after description resumes, and the frame closes.
5. Stop wins before successful-evidence commit: RED exit 1,
   `wgc_self_test=fail type=InvalidOperationException`; GREEN exit 0, cases=10.
   Stop/Commit share a lock; no success metadata is committed after Stop wins.

The other seven final regressions cover managed ABI sizes/offsets, balanced
confirmed Close/Release and repeated cleanup, failed Close clearing pixels,
valid cropped owned pixels only after frame Close, marker-only hashing with
unrelated outside bytes, Stop inside frame Dispose, and failed QI with a nonzero
outref. Fakes replace only the native borrowed-frame/COM boundaries. They do not
simulate WGC/DWM success or prove native fault handling.
